# 架构决策

## 推荐架构

历史模拟器默认采用“单一运行入口 + 多规则文件”的结构：

1. 世界主持器 skill
2. 人物名册与人物规则
3. 势力与制度关系图
4. 世界事件引擎
5. 天气与气候引擎
6. 状态账本
7. 小说化记录器

这比“每个角色一个独立 skill”更适合历史模拟器。

## 为什么不默认每人一个 skill

### 1. skill 适合被触发，不适合长期驻留

一个历史模拟器里的人物是持续存在的，不是临时被调用一次的工具。

### 2. 多 skill 会放大上下文漂移

人物越多，越容易出现：

- 历史立场不一致
- 状态不同步
- 同一事件多版本解释
- 世界规则互相打架

### 3. 世界主持器更适合统一裁决

历史模拟器需要一个统一的裁决层来处理：

- 谁知道什么
- 谁能做什么
- 什么会产生连锁反应
- 天气、财政、军情如何共同影响结果

这个角色更像 Game Master，而不是多个平级 skill 互相对话。

## 推荐的“概念 agent”建模方式

人物不做成独立安装 skill，而是做成结构化人物卡。

每个人物卡至少包含：

- 基本身份与史实锚点
- 公开目标
- 隐藏压力
- 关键关系
- 资源与权力来源
- 认知边界
- 行动偏好
- 底线与恐惧
- 遇到气候、战争、宫廷压力时的反应倾向

## 世界状态层

建议至少维护以下状态层：

- 时间：日期、节气、季节
- 天气：日常天气、异常天气、长期气候
- 政治：朝廷稳定度、地方服从度、派系张力
- 财政：粮、银、税赋、军费
- 军事：兵力、机动、补给、士气
- 民情：治安、饥荒、谣言、流民
- 主角：威望、健康、资源、盟友、敌意
- 领土：区域控制权、控制强度、驻军、民心、边境冲突
- 物产：可用作物、引入进度、外部贸易接触
- 已知世界：已探明区域、外部区域接触状态、地图扩展进度

## 史实层级

建议在目标模拟器内部使用四层事实标签：

- `史实锚点`
- `合理推演`
- `用户设定`
- `演化结果`

这些标签可以写在规则文件和状态记录里，不一定每次都展示给玩家。

## 天气与气候层

天气规则至少分三层：

1. 长期气候底盘
   - 例如小冰河期、暖湿期、连年旱灾背景
2. 季节性天气
   - 例如春旱、夏涝、秋收、冬雪
3. 单回合异常事件
   - 例如暴雪、蝗灾、冰封、河道决口、疫病气候触发

## 记录层

每回合同时维护：

- 结构化日志
- 小说化正文

结构化日志服务于”模拟一致性”，小说化正文服务于”可读性与沉淀”。

## 地图系统架构

地图系统分三层，与现有状态层并行运作：

- L1 地理底盘（静态）：区域地形、资源、气候、邻接关系
- L2 领土控制（动态）：区域所有权、控制强度、驻军、民心
- L3 可视区域（认知）：主角对每个区域的可见性等级

### 地图与现有系统的联动

| 联动系统 | 联动方式 |
|----------|----------|
| 天气引擎 | 天气影响结合地形产生不同后果（暴雨 + 水网 = 洪涝，暴雨 + 山地 = 泥石流） |
| 事件引擎 | 领土变更触发事件（叛乱、独立、投降）；区域控制触发条件事件 |
| 势力系统 | 势力必须有领土，实力来源于控制区域的资源产出 |
| 财政系统 | 税收来源于控制区域，控制强度决定实际收税效率 |
| 军事系统 | 行军受地形影响，补给线依赖领土连通性 |
| 知晓模型 | 主角只能看到可视区域内的信息 |

### 地图扩展机制

已知世界范围不是固定的。通过贸易、外交、军事探索，玩家可以逐步接触外部区域：

1. 探知 -- 通过商人/流民/使节听说外部区域
2. 接触 -- 派遣使节或商队建立初步联系
3. 融入 -- 持续交流后外部区域进入已知世界

地图扩展是获取外部物产（如高产作物）的前提条件。

## 物产系统架构

物产系统管理作物和技术的引入时间线，确保历史合理性。

### 核心规则

任何作物/物产不能无中生有，必须通过以下渠道之一获取：

1. 历史性引入 -- 按史实时间线自然传播
2. 主动探索 -- 玩家通过地图扩展主动获取
3. 系统奖励 -- 仅限有”系统”设定的模拟器
4. 意外获取 -- 低概率随机事件

### 穿越者知识约束

穿越者知道某作物存在，不等于能获取该作物。知识与获取渠道是两回事：

- 三国穿越者知道土豆存在，但美洲尚未被任何中国可达势力发现
- 占城稻在三国时期理论上可通过交州获取，但需要主动派人寻找
- 作物的获取受限于：地理可达性、贸易路线、外交关系、运输条件
