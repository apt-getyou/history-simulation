# 目标模拟器运行规则

目标模拟器运行时，建议遵循以下顺序。

## 人物信息分层加载

**不全量加载人物卡，避免上下文污染。** 详见 `references/runtime-scheduling.md`。

三层结构：

| 层级 | 内容 | 加载时机 | 单人token |
|------|------|----------|-----------|
| 总览表 | 姓名、状态、身份、阵营、位置、关系 | 始终常驻 | ~20 |
| 摘要卡 | + 目标、压力、行动倾向、认知边界 | 本回合相关 | ~100 |
| 完整卡 | 七层模型全部信息 | 需要精细化决策 | ~500 |

摘要卡加载条件（满足任一）：与主角同场景、被事件涉及、信息传播链涉及、玩家指定互动。

完整卡加载条件（摘要卡条件 + 任一）：复杂决策、深度互动、性格偏离检查、经历塑造。

## 回合循环

1. 推进当前日期与时间段
2. 结算季节、天气、长期气候
3. 结算固定世界事件
4. 结算条件触发事件，确定本回合涉及的人物
5. **确定人物加载清单**：基于事件、场景、传播链
6. **按需加载人物信息**：总览表常驻 + 摘要卡按需 + 完整卡极少
7. 结算幕后人物和势力的私下动作（只处理已加载的人物）
8. 根据传播链与暴露条件结算”谁知道了什么”
9. 读取并结算玩家行动
10. 更新状态账本
11. 输出玩家可见结果
10. 写入小说化记录

## 推荐时间机制

不要默认固定成“一回合一天”。

更推荐“变焦回合”：

- 宏观回合：以旬、半月或月为单位，推进财政、军情、民情、气候
- 微观场景：遇到关键事件时，临时切到按天或按场景推进

适用建议：

- 皇帝、执政、王朝经营题材：默认旬或月
- 城市求生、流亡、行军题材：可默认日
- 阴谋、谈判、政变题材：允许一个宏观回合内嵌多个场景子回合

## 信息不对称规则

### 世界主持器与玩家视角分离

世界主持器可以维护全局状态，但默认不能把全局状态直接展示给玩家。

玩家默认只看到以下来源的信息：

- 主角亲眼所见
- 主角亲耳所闻
- 主角收到的奏报、密报、口头汇报
- 主角主动调查、审讯、查账、布谍后获取的结果
- 已公开爆发、无法继续隐藏的事件后果

### 人物知晓边界

每个角色只能基于以下信息行动：

- 自身经历
- 自身掌握的资源与密报
- 所属势力内部流通的信息
- 可合理推断出的判断

禁止角色因为世界主持器知道，就自动知道。

### 隐藏信息分层

建议至少分成五层：

- `global_truth`：世界主持器掌握的全局真相
- `private_known`：仅个人或极小圈子知道
- `faction_known`：势力内部知道
- `public_known`：社会面公开知道
- `player_known`：主角当前知道

### 暴露机制

隐藏信息不应凭空进入玩家视野，至少通过以下一种渠道：

- 当场撞见
- 正式上报
- 密探回报
- 查账、审讯、搜检、侦缉成功
- 流言发酵成可验证事件
- 事件后果大到无法继续掩盖

### 私密账本

关键人物和势力应维护自己的私密账本，记录：

- 私下行动
- 未公开目标
- 当前已知信息
- 错误判断
- 预期掩盖方式
- 曝光条件

玩家默认不能直接读取这些账本。

## 每回合输出结构

建议使用以下四段：

### 1. 世界简报

- 当前日期
- 天气与气候
- 玩家当前已知的关键事件
- 玩家当前已知的局势变化

### 2. 互动正文

用连续叙事方式呈现主角所处场景、人物反应和冲突推进。

### 3. 结果与可选行动

- 玩家行动结果
- 代价与收益
- 下一步可选方向

### 3.1 情报来源

如果本回合玩家得知了新信息，要注明来源：

- 面奏
- 邸报
- 密报
- 口供
- 巡查
- 流言
- 亲见

### 4. 状态变更

- 政治
- 财政
- 军事
- 民情
- 主角个人
- 其他关键标记

## 记录原则

### 结构化账本

必须保留：

- 回合编号
- 日期
- 地点
- 天气
- 事件
- 参与角色
- 主角行动
- 结果
- 状态变化
- 新增知晓事项
- 信息来源

### 小说化正文

必须能单独阅读成文，但不要脱离结构化账本。

## 冲突处理

当史实、推演、设定冲突时，按以下优先级：

1. 用户明确指定的核心设定
2. 已写明的不可变史实
3. 先前回合已生效的演化结果
4. 新一轮合理推演

当“全局真相”和“玩家当前认知”冲突时：

1. 结算按全局真相执行
2. 展示按玩家当前认知输出
3. 待满足暴露条件后再修正玩家认知

## 完结系统

模拟器必须能在有限回合内结束。不能无限续下去。

### 完结触发条件

以下条件满足任意一条，立即进入完结结算：

**硬性完结（不可阻止）：**

| 条件 | 说明 |
|------|------|
| 主角死亡 | 无修仙/长生设定时，主角死亡 = 结局 |
| 胜利条件达成 | 用户定义的核心目标已完成 |
| 失败条件达成 | 用户定义的核心目标已不可能实现 |
| 时间上限到达 | 超过设定的时间限制或主角自然寿命 |

**软性完结（可延期一次）：**

| 条件 | 说明 |
|------|------|
| 局面长期停滞 | 连续 N 回合无重大事件、无状态变化、玩家无新行动 |
| 核心势力全部消亡 | 主角所属势力已不存在，且无法重建 |

软性完结触发时，提醒玩家："局面已趋于稳定/僵局，是否继续？"玩家选择继续则重置停滞计数器，选择结束则进入完结结算。

### 结局类型

| 类型 | 判定 | 示例 |
|------|------|------|
| **大胜** | 核心目标超额完成 | 崇祯不仅守住大明，还收复辽东 |
| **胜利** | 核心目标完成 | 崇祯稳定朝局，大明延续 |
| **惨胜** | 核心目标完成但代价惨重 | 崇祯守住大明但失去半壁江山 |
| **开放结局** | 未胜利也未失败，但时间到了 | 崇祯寿终正寝，大明尚在但隐患仍在 |
| **失败** | 核心目标不可能实现 | 崇祯被推翻，大明覆灭 |
| **惨败** | 不仅失败，局面比历史更糟 | 崇祯导致大明提前崩溃，天下大乱 |

### 每回合检查完结条件

回合结算的最后一步，检查完结条件：

```
完结检查流程：
  1. 主角是否死亡？
     - 是 → 进入完结结算（结局类型取决于目标完成度）
  2. 胜利条件是否达成？
     - 是 → 进入完结结算（胜利类结局）
  3. 失败条件是否达成？
     - 是 → 进入完结结算（失败类结局）
  4. 是否超过时间上限？
     - 是 → 进入完结结算（开放结局或按完成度判定）
  5. 局面是否长期停滞？
     - 是 → 提示玩家选择是否继续
  6. 以上都不是 → 继续下一回合
```

### 完结结算输出

完结时必须输出以下内容：

**1. 结局宣告**

一句话说明结局类型和结果。例如："大结局 -- 惨胜。崇祯守住了大明，但辽东尽失，国库空虚，继承人年幼。风雨飘摇。"

**2. 编年史摘要**

从开局到结局的关键事件时间线，按年或按阶段列出：

```
| 年份 | 关键事件 |
|------|----------|
| 1644 | 主角穿越为崇祯，开局 |
| 1644 | 裁撤驿站，引发民变 |
| 1645 | 成功稳住京营，李自成暂缓进军 |
| 1647 | 与皇太极议和，争取喘息时间 |
| 1650 | 收复洛阳，平定中原流寇 |
| 1653 | 辽东反攻失败，洪承畴降清 |
| 1656 | 国库耗尽，加征三饷引发新民变 |
| 1660 | 崇祯病逝，太子即位，大明延续但元气大伤 |
```

**3. 核心指标最终值**

| 指标 | 最终值 | 开局值 | 变化 |
|------|--------|--------|------|
| 国库 | 20 | 50 | -30 |
| 民心 | 45 | 40 | +5 |
| 边境安全 | 30 | 20 | +10 |

**4. 与历史轨迹对比**

如果用户选择的历史时期有对应的历史真实走向，列出对比：

```
| 维度 | 历史真实 | 本局结果 |
|------|----------|----------|
| 崇祯结局 | 自缢煤山 | 病逝，大明延续 |
| 明朝命运 | 1644年灭亡 | 延续但衰弱 |
| 满清 | 入主中原 | 盘踞辽东，未入关 |
```

**5. 遗产评估**

主角的作为对后世（模拟器时间线之后）的预期影响：

- 政治遗产：留下的制度、政策、人事安排
- 军事遗产：边防态势、军队状况
- 经济遗产：财政健康度、土地制度
- 文化遗产：对后世观念的影响

**6. 游玩统计**

- 总回合数
- 游玩时长（真实世界时间）
- 关键决策次数
- 历史偏离度最终值

### 继承：基于完结世界创建新模拟器

完结后，玩家可以选择"以此世界为基础，开启新一代模拟器"。

#### 继承模式

| 模式 | 说明 | 新主角 | 示例 |
|------|------|--------|------|
| **血脉继承** | 玩旧主角的继承人（子嗣/弟子） | 旧主角后代 | 崇祯死后，太子即位 |
| **旁系继承** | 玩同世界的其他人物 | 与旧主角不同的人 | 崇祯死后，玩家改玩洪承畴 |
| **时间跳跃** | 跳到 N 年后，世界自行演化了 N 年 | 新时代的新人物 | 跳到50年后，玩崇祯孙子 |
| **敌对阵营** | 换到对立面 | 旧主角的对手 | 玩完崇祯后，改玩皇太极 |

#### 继承时携带的数据

```
旧模拟器完结状态
├── 携带（直接继承）
│   ├── 世界状态（政治/财政/军事/民情/天气）
│   ├── 存活人物 + 完整人物卡
│   ├── 归档池 + 遗产池
│   ├── 血脉追踪表
│   ├── 制度和法律
│   ├── 势力版图
│   ├── 地理和资源分布
│   ├── 编年史（完整记录）
│   └── 历史偏离度
│
├── 转换（需要重新处理）
│   ├── 主角身份 → 新主角
│   ├── 胜利/失败条件 → 重新定义
│   ├── 信息可见性 → 基于新主角重新切分
│   ├── 人物性格可塑性 → 基于新 start_date 重新评估
│   └── 事件引擎 → 清空历史事件池，只保留条件触发事件
│
└── 丢弃（不继承）
    ├── 旧主角的私密账本（已封存）
    ├── 旧主角的玩家视角信息
    └── 旧模拟器的 state.json
```

#### 关键变化：历史参考材料的切换

第一代模拟器有真实历史可以对比（三国志、三国演义等）。
第二代开始，"历史"变成了第一代模拟器的实际运行记录。

```
参考材料层级：

第一代模拟器：
  史料参考 = 正史 + 演义 + 学术研究
  对比基线 = 真实历史

第二代模拟器：
  史料参考 = 第一代编年史 + 第一代人物档案
  对比基线 = 第一代的实际走向

第三代模拟器：
  史料参考 = 第一代编年史 + 第二代编年史
  对比基线 = 前两代的实际走向
```

这意味着：
- **冲突检测**（阶段 2）在继承模式中不再需要，因为只有一个"版本"：上一代的实际记录
- **来源账本**从"史料来源"变成"上一代模拟器记录"
- **人物提炼**从"史料提炼"变成"上一代人物卡 + 这一新经历的推演"
- **事件引擎**中不再有"历史事件"，所有事件都是条件触发的推演事件

#### 继承模式下的生成流程（简化版）

继承不走完整的 9 阶段流程。跳过数据收集和冲突检测，直接从已有数据开始：

```
继承模式流程：

[1] 读取旧模拟器完结状态
    → 世界状态、存活人物、遗产池、编年史

[2] 用户选择继承模式（血脉/旁系/时间跳跃/敌对）

[3] 确定新主角和新目标
    → 访谈（简化版，只确认主角、目标、完结条件）

[4] 转换数据
    → 重新切分信息可见性（基于新主角）
    → 重新评估人物可塑性（基于新 start_date）
    → 处理时间跳跃期间的自动演化（如果选择了时间跳跃）

[5] 生成新模拟器 skill 包
    → 复用旧文件结构
    → 替换主角相关内容
    → 更新事件引擎

[6] 一致性校验

[7] 交付
```

#### 时间跳跃的自动演化

如果玩家选择"跳到 N 年后"，需要推演 N 年间世界的自行演化：

```
时间跳跃演化规则：

1. 确定跳跃年数 N
2. 分段推演（每段 5-10 年）
3. 每段推演：
   a. 天气气候按规则持续运行
   b. 人物自然衰老、死亡、出生
   c. 势力按当前趋势惯性运行
   d. 重大事件按条件触发（不再有历史事件锚定）
   e. 制度按既有规则执行
4. 产出：
   a. 跳跃期间编年史摘要
   b. 跳跃后世界状态快照
   c. 跳跃后存活人物清单
   d. 新出生人物清单
   e. 去世人物归档
```

时间跳跃推演不产生详细的小说化记录，只产出结构化摘要。详细内容在新模拟器运行时由新主角的视角揭示。
