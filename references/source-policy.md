# 史料来源规则

历史模拟器必须把”信息来源可靠性”当成硬规则。

## 来源优先级

### A 级：一手史料

包括但不限于：

- 正史、实录、起居注
- 奏疏、诏令、书信、日记、笔记
- 地方志、碑刻、档案、出土文书
- 当事人文集

### B 级：高质量现代研究

优先选择：

- 学术专著
- 核心期刊论文
- 大学出版社或权威出版社作品
- 可靠学者的专题研究

### C 级：线索参考（不进入断言链）

C 级来源**仅用于发现检索线索**，不可作为任何断言的直接依据。

包括：

- 维基百科、百度百科等可编辑百科 -- 发现"该查什么原始文献"
- 博物馆、大学课程资料
- 有引用链的综述 -- 追溯到原始来源后才能使用
- 其他网络公开资料

**规则**：C 级来源发现线索后，必须追溯到 A/B 级原始文献验证，才能形成断言。

## 用户提供的本地著作来源

用户可将本地文件作为史料来源，直接参与数据收集和冲突检测流程。

### 适用场景

- 用户有特定主题的著作全文（如《三国演义》《三国志》《资治通鉴》）
- 用户有自行整理的史料笔记或研究文档
- 用户有特定视角的文献（如外文译本、罕见史料）

### 来源等级由用户指定

本地来源不自动判定等级，由用户在 `local_sources` 配置中指定：

| 用户指定 | 等同于 | 说明 |
|----------|--------|------|
| `source_type: primary, source_tier: A` | A 级一手史料 | 用户确认该文件为原始史料 |
| `source_type: fiction, source_tier: B` | B 级文学来源 | 文学作品，有较高参考价值 |
| `source_type: academic, source_tier: B` | B 级学术研究 | 学术著作或研究文献 |
| `source_type: popular, source_tier: C` | C 级通俗参考 | 通俗读物或整理资料 |

### 支持的文件格式

| 格式 | 说明 |
|------|------|
| `.txt` | 纯文本，最常用 |
| `.md` | Markdown 文本 |
| `.csv` | 表格数据 |
| `.json` | 结构化数据 |
| PDF | 需用户自行转为 TXT 后使用 |

### 本地来源的处理流程

本地来源**不做 RAG 式分块处理**。由 AI agent 直接阅读原文，保持信息完整性。

1. 脚本生成 `source-catalog.json`（元数据 + 阅读策略），不读取文件内容
2. AI agent 根据 `reading_strategy` 决定阅读方式：

| 策略 | 触发条件 | AI agent 行为 |
|------|----------|-------------|
| `full` | < 200K 字符 | 全文阅读，按七层模型提取 |
| `chapter` | >= 200K 字符，检测到章节标记 | 读取章节目录，选择相关章节阅读 |
| `segments` | >= 200K 字符，无章节但有空行段落群 | 按段落群分段阅读 |
| `linear` | >= 200K 字符，无自然分段 | 按 offset 分批阅读，每批 10% 重叠 |

3. AI agent 将提取结果写入 `data/raw/` 的实体 JSON 文件
4. 本地来源参与冲突检测，与 Web 搜索来源平等比较
5. 在蓝本选择流程中，本地来源按其指定的等级参与决策

**为什么不做分块**：
- 人物描写、事件叙述跨段落是常态，机械分块切断上下文
- 纯关键词匹配无法捕获代词、隐喻、隐含指代
- 三重验证需要完整叙事弧，碎片化后验证失效
- 大上下文模型（200K+ token）可直接处理完整文件

### 本地来源的约束

- 本地来源的内容以文件为准，不做任何修改
- 如果本地来源与 Web 搜索来源冲突，按正常冲突解决流程处理（用户选择蓝本）
- 推荐使用大上下文模型（200K+ token，推荐 1M 上下文模型）以确保能完整阅读来源文件
- 文件编码自动检测（UTF-8 / GBK / Big5 等），无法解码时报错
- 文件编码自动检测（UTF-8 / GBK / Big5 等），无法解码时报错

## 禁止直接作为史料的来源

- 无引用的 AI 生成摘要
- 自媒体改写文
- 营销号、搬运号
- 未标出处的短视频解说
- 聚合站的二次转述

## 断言入库规则

### 强断言

可以写进模拟器硬规则的断言，至少满足其一：

- 一条明确的一手史料直接支持
- 两条独立可靠来源交叉支持

### 弱断言

只能写成“倾向”“可能”“学界常见解释”的内容：

- 仅有单一二手来源
- 来源间存在明显冲突
- 只能从行为倒推出心理

## 来源账本

每个目标模拟器都应生成 `references/10-source-ledger.md`。

至少记录：

- 断言或规则
- 来源等级
- 具体出处
- 用途
- 置信度
- 是否存在争议

## 史料溯源与偏倚控制

详细的来源完整性方案见 `references/source-integrity.md`，包含：

- 数据源分层策略（C 级仅作线索，不进断言链）
- 文献偏倚标注（AI 辅助初筛 + 用户确认）
- 证据链设计（每条断言精确到原文位置和引用）
- 叙事依赖检测（识别假交叉验证）
- 生成物中的溯源呈现（断言ID关联）

## 诚实边界

当材料不足时，生成器必须：

- 明确说“不足以确认”
- 降级为弱断言
- 避免把推测写成史实
