# 模式 B：继承存档

## 触发条件

用户提供已完结的模拟器存档目录路径，要基于这个存档创建新模拟器。

触发词：继承、续玩、下一代、二代、以此世界为基础、继续

## 前提检查

1. 用户提供存档目录路径
2. 该目录包含完整的记录文件（编年史、人物卡、state.json 等）
3. 该模拟器已经过完结结算（不是中途退出的残档）

如果不满足前提，要求用户补充或重新选择。

## 进度追踪

继承模式有独立的阶段编号（B-0 到 B-6），不与模式 A 混用。

```json
{
  "sim_slug": "{new-sim-slug}",
  "mode": "B",
  "current_phase": "B-0",
  "parent_sim": "{old-sim-slug}",
  "phases": {
    "B-0": { "status": "in_progress" },
    "B-1": { "status": "pending" },
    "B-2": { "status": "pending" },
    "B-3": { "status": "pending" },
    "B-4": { "status": "pending" },
    "B-5": { "status": "pending" },
    "B-6": { "status": "pending" }
  }
}
```

## 流程

### B-0：读取存档

1. 确认存档目录路径
2. 验证存档完整性：
   - 存在 `records/` 目录，包含编年史记录
   - 存在 `characters/` 目录，包含人物卡
   - 存在完结结算记录（结局类型、最终状态）
3. 读取存档的核心数据：
   - 最终 state.json
   - 势力格局
   - 存活人物清单
   - 关键遗产
4. 如果存档不完整，要求用户补充或重新选择

### B-1：确定继承模式

让用户选择：

| 模式 | 说明 | 新主角 |
|------|------|--------|
| **血脉继承** | 旧主角的继承人（子嗣/弟子） | 用户指定或由存档推导 |
| **旁系继承** | 同世界的其他存活人物 | 用户指定 |
| **时间跳跃** | 跳到 N 年后，世界自行演化了 N 年 | 新时代的新人物 |
| **敌对阵营** | 旧主角的对手/敌对方 | 用户指定 |

### B-2：确定新主角和新目标（简化访谈）

只确认以下内容，不需要完整访谈：

- 新主角是谁（从存活人物中选择，或由血脉/时间跳跃生成）
- 新主角的核心目标（胜利条件）
- 新主角的失败条件
- 时间上限
- 是否有追加设定（新的架空元素）
- 回合粒度和记录模式是否沿用或调整

其余参数从存档继承。

### B-3：数据转换

**这是模式 B 的核心工作。**

| 转换项 | 说明 |
|--------|------|
| **信息可见性重切** | 基于新主角重新划定谁知道什么。旧主角知道但新主角不知道的信息，重新归入"未知" |
| **人物可塑性重评** | 基于新的 start_date 重新评估每个人物的可塑性等级 |
| **人物卡更新** | 存活人物的经历补充上一代的编年史内容 |
| **事件引擎重建** | 清空历史事件池，只保留条件触发事件。来源从"史料"变为"上一代记录" |
| **来源账本更新** | 所有断言的来源改为"第 N 代模拟器记录" |
| **血脉追踪更新** | 合并上一代的出生/死亡记录 |
| **遗产池继承** | 上一代的活跃遗产直接继承 |
| **时间跳跃演化**（如适用） | 推演跳跃期间的世界变化 |

**时间跳跃的自动演化**（如适用）：

如果用户选择了时间跳跃模式，需要推演跳跃年数间的世界变化：
- 分段推演（每段 5-10 年）
- 天气气候按规则持续运行
- 人物自然衰老、死亡、出生
- 势力按当前趋势惯性运行
- 不产出详细的小说化记录，只产出结构化摘要
- 详细内容在新模拟器运行时由新主角的视角逐步揭示

### B-4：生成新模拟器 skill 包

与模式 A 的阶段 6 相同（读取 `phases/phase-6-generate.md`），但数据来源不同：

| 维度 | 模式 A（全新） | 模式 B（继承） |
|------|--------------|--------------|
| 数据 | web 搜索收集的史料 | 上一代存档文件 |
| 来源 | 正史/演义/学术研究 | 上一代模拟器记录 |
| 事件 | 历史事件（条件触发） | 纯条件触发（无历史锚点） |
| 对比基线 | 真实历史 | 上一代的实际走向 |

文件结构：

```
{sim-slug}-gen{N}/                   # 第 N 代模拟器
├── .engine-meta.json
├── SKILL.md
├── dashboard.html
├── state.json
├── data/
│   ├── inherited-from.md            # 继承来源说明
│   └── gen{N-1}-archive/            # 上一代存档（只读）
│       ├── chronicle.md
│       ├── final-state.json
│       └── character-archive/
├── references/                      # 同模式 A 的 15 个文件
├── characters/
│   ├── active/
│   ├── waiting/
│   └── archive/
└── records/
```

### B-5：一致性校验

与模式 A 的阶段 7 相同（读取 `phases/phase-7-validate.md`），额外检查：

- 新主角的信息可见性是否正确（不知道旧主角的私密信息）
- 存活人物的年龄和状态是否与上一代完结时间衔接
- 遗产池是否正确继承
- 时间跳跃（如有）的演化是否合理

### B-6：交付

汇报内容：

- 继承来源（上一代模拟器名称、完结类型）
- 继承模式和新主角
- 世界状态与上一代完结时的主要变化
- 新的胜利/失败条件
- 新模拟器后续可如何继续迭代

## 完成标准

- 新模拟器 skill 包已生成
- 一致性校验通过
- 交付汇报已输出
- 进度标记为 completed

- B-3 数据转换是最耗上下文的子阶段
- 时间跳跃演化需要分批推演（每段 5-10 年）
- B-4 包生成复用模式 A 的分批策略
