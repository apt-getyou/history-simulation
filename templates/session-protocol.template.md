## 回合时序

每个回合代表 {{turn_granularity}}，按以下顺序结算：

### 1. 日期推进

- 推进一个时间单位
- 更新季节（影响天气结算）
- 检查时间上限

### 2. 天气结算

- 按季节天气表确定本月基础天气
- 掷骰确定是否触发异常天气
- 天气影响写入所有关联系统

### 3. 事件触发

- 检查条件触发事件：遍历所有事件卡片，检查触发条件
- 已触发事件推进：检查活跃事件的下一阶段
- 天气触发事件：旱灾/蝗灾/瘟疫等

### 4. 人物加载

- 基于事件涉及的人物确定加载清单
- 总览表常驻 + 摘要卡按需 + 完整卡极少
- 上下文预算：人物信息不超过50%

### 5. 势力与人物行动

- 按加载的人物列表结算行动
- 每个人物基于动机、约束、信息做出行动
- 势力级别的行动（军事部署、外交等）

### 6. 幕后动作

- 不对玩家可见的秘密行动
- 信息传播：秘密按传播链扩散
- 更新私密账本

### 7. 主角行动

- 向玩家展示当前局势（仅主角可知信息）
- 等待玩家决策
- 决策影响写入因果链

### 8. 状态更新

- 所有系统结算
- 更新主角知晓范围
- 检查信息暴露条件

### 9. 输出

- 世界简报（结构化）
- 互动正文（小说化）
- 情报变化
- 状态变更

### 10. 记录写入

- 将本回合写入 `records/ledger/turn-NNN.md`（结构化账本）
- 将小说化正文写入 `records/chronicle/turn-NNN.md`
- 更新涉及人物的 `characters/active/*.md`
- 更新 `state.json`
- 更新 `.engine-meta.json` 中的 `turn_count`

### 11. 完结检查

| 领域 | 字段 | 月度变化 | 说明 |

**基线表示例（王朝末期默认值）**：

| 领域 | 字段 | 月度变化 | 说明 |
|------|------|----------|------|
| 财政 | 库银 | -3 | 日常开支（俸禄、宫廷、维修） |

| 财政 | 粮储 | +8 | 漕粮入京（仅当运河通畅时） |
| 军事 | 补给 | -2 | 常规消耗 |
| 民情 | 流民 | +1 | 自然增长（灾荒期间翻倍） |
| 民情 | 治安 | -1 | 流民增长副作用 |

**基线应用规则**：

1. 基线在每回合步骤 9 首先应用
2. 事件效果在基线之后叠加
3. 玩家决策效果在事件效果之后叠加
4. 所有数值在 0-100（或 max 值）之间截断
5. 季节修正：冬季粮储消耗 +50%，夏季兵源补充 +5%

## 决策影响量化表

玩家做出的每个决策都必须量化为具体的状态变更。世界主持器在步骤 8 结算时使用此表。

### 量化规则

| 决策类型 | 量化维度 | 典型消耗 | 典型效果 | 滞后期 |
|----------|----------|----------|----------|--------|
| 人事任免 | 威望、派系 | 无直接消耗 | 派系张力 +/- 5~15 | 即时 |
| 军事调遣 | 兵力、补给、军费 | 军费 -5~15 | 取决于战果 | 1-3 月 |
| 财政决策 | 库银、粮储 | 规模决定 | 取决于类型 | 1-6 月 |
| 外交决策 | 威望、银两 | 使节费 -2~5 | 取决于对手反应 | 2-4 月 |
| 赈灾决策 | 库银、粮储 | 灾区人口 x 等级 x 单位 | 民情 +5~15 | 1-2 月 |
| 情报决策 | 人力、银两 | -2~5 | 取决于目标 | 1-3 月 |

### 量化记录格式

每个决策在回合记录中按以下格式写入：

```
决策: [描述]
  ├─ 消耗: [字段] -X ([说明])
  ├─ 直接效果: [字段] +X/-X ([说明])
  ├─ 延迟效果: [字段] +X/-X ([回合数]月后)
  └─ 风险: [概率]% [后果描述]
```

### 决策效果上限

单次决策不能造成超过以下限制的状态变更：

- 单项指标变化不超过 +/- 20（除非终结性事件）
- 消耗类决策的总消耗不超过当前持有量的 50%
- 威望单回合变化不超过 +/- 10
- 派系张力单回合变化不超过 +/- 15

## 脚本支持

本模拟器支持回合结算脚本自动化。如果 `scripts/turn-engine.mjs` 存在：

1. 在步骤 1-4 前运行脚本处理日期推进、天气结算、事件扫描、人物清单
2. 读取 `turn-settlement.json` 获取结算结果
3. 继续执行步骤 5-8（需要 AI 创造性判断的部分）
4. 步骤 9 的基线消耗和数值更新已由脚本完成
5. 在步骤 10-11 间运行 `scripts/record-writer.mjs` 写入记录

如果脚本不存在，所有步骤由 AI 手动执行。

## 静观回合

玩家可以选择"静观"——不主动做出任何决策，让事态自然发展。

### 静观规则

1. 静观时，只应用月度基线 + 天气效果 + 已触发事件的默认结果
2. 不消耗额外资源（无决策成本）
3. 世界按人物和势力的自主意愿行动
4. 静观期间主角不获取额外情报
5. **成长模式例外**：当 `protagonist.status.growth.decision_capacity` 为 `none` 时，不适用静观限制。幼年期每回合自动视为静观，不计入连续静观计数。
6. 成年主角连续静观不超过 3 回合（第 4 回合强制要求决策）

### 静观效果

| 效果 | 说明 |
|------|------|
| 威望 | -2（消极形象） |
| 信息 | 不获取新情报 |
| 事件 | 按默认轨道推进（通常是不利方向） |
| 局势 | 各势力按自身利益行动 |

## 赈灾流程

当发生灾荒（旱灾、蝗灾、洪涝、疫病等）时，赈灾是独立完整的决策流程。

### 赈灾决策步骤

1. **灾情评估**：确定受灾区域、人口、等级（1-5 级）
2. **资源盘点**：计算所需赈灾资源（粮储 + 库银）
3. **方案选择**：
   - 全力赈灾：消耗 = 灾区人口 x 灾害等级 x 单位赈灾费
   - 有限赈灾：消耗减半，效果减半
   - 不赈灾：无消耗，但民情崩塌
4. **执行效果**：
   - 全力赈灾成功：民情 +5~15，控制力 +0.03，阻断灾荒累积
   - 有限赈灾：民情 +2~8，部分阻断
   - 不赈灾：民情 -15/月，流民 +10/月，灾荒累积
5. **延迟判定**：赈灾必须在灾害发生的 **1 个月内** 启动，否则效果递减

### 赈灾成本计算

```
赈灾总成本 = 灾区人口(万人) x 灾害等级 x 0.5（库银点） + 灾害等级 x 2（粮储点）
```

## 成长模式回合规则

当 `references/growth-system.md` 存在时，以下规则覆盖标准回合流程的部分步骤。

### 年龄阶段与回合粒度

| 阶段 | 年龄 | 回合粒度 | 每回合时间跨度 |
|------|------|---------|--------------|
| 幼年 | 0-6 | 季度/半年 | 3-6个月 |
| 童年 | 7-12 | 季度 | 3个月 |
| 少年 | 13-16 | 月 | 1个月 |
| 青年+ | 17+ | 月 | 1个月 |

### 回合流程变更

#### 幼年期（decision_capacity: none）

跳过标准流程步骤 7（主角行动），替换为自动推进：

1. 推进日期（季度/半年）
2. 结算天气和气候
3. 结算事件（仅旁观事件和成长事件）
4. 加载人物（仅身边人）
5. 结算身边人物行为
6. 结算幕后动作
7. **自动生成主角行为**（基于性格、年龄和环境）
8. 结算教育效果（如有教师）
9. 更新状态、性格维度
10. 输出成长叙事
11. 检查阶段转换条件
12. 写入记录和 state.json

**输出格式**：

```
### 季节变化
[季节描写，以感官为主]

### 成长记录
[主角的成长叙事，侧重情感和认知]

### 教育进展
[本阶段的教育内容和效果]

### 身边人的变化
[身边重要人物的状态变化]

### 性格变化
[性格维度的变化，用直观描述代替数值]
```

#### 童年期（decision_capacity: minimal）

步骤 7 替换为有限选择：

1. 提供简单A/B选择（如：学习方向、玩伴选择、课余活动）
2. 选择影响性格维度变化方向
3. 不涉及政治/军事/财政决策

#### 少年期（decision_capacity: limited）

步骤 7 增加建议权：

1. 可旁听政务/军议
2. 可提出建议（建议权重 = 30-50%，由GM判定）
3. 可做独立决定（但限于个人范围：学习、出行、社交）
4. 重大决策仍需监护人批准

### 成长事件触发

每个成长回合结束后，检查成长事件池（`references/growth-event-pool.md`）：

1. 根据当前年龄阶段确定对应事件池
2. 根据触发概率判定是否触发成长事件
3. 选择与当前情境匹配的事件
4. 应用性格效果
5. 记入 `protagonist.status.growth.milestones_reached`

### 阶段转换

当主角年龄达到阶段转换点时：

1. 在该回合末尾输出阶段转换叙事
2. 更新 `protagonist.status.growth` 中所有相关字段
3. 调整回合粒度
4. 更新信息渠道
5. 扩展活动范围（L0层）

转换叙事格式：

```
### 成长里程碑

你已经 {{new_age}} 岁了。

{{stage_transition_narrative}}

从现在起，你{{new_ability_description}}。
```
